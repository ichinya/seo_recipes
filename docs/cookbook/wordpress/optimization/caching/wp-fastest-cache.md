# WP Fastest Cache

WP Fastest Cache — один из самых популярных плагинов кэширования страниц для WordPress. Его рекомендуют во многих хостинговых инструкциях, обещая ускорение «в 2–3 раза». Я проверил плагин тем же нагрузочным тестом, каким гонял [Breeze и Varnish](./caching.md), — и заодно нашёл пару граблей, о которых инструкции молчат.

## Что умеет

* Кэширование страниц для гостей (в бесплатной версии).
* Очистка кэша при публикации новой записи и при обновлении существующей.
* Предподготовка (прогрев) кэша — генерация по расписанию.
* Браузерное кэширование (через .htaccess — то есть только на Apache).
* Минификация HTML/CSS — частично платная, как и CDN-интеграция.

Настройка занимает минуту: галочка «Кэширование», очистка при публикации/обновлении, при желании — прогрев. Больше для базового сценария и не требуется.

## Замеры на живом сайте с nginx

Стенд: VPS (CloudPanel, nginx + PHP-FPM 8.5), сайт на ~2300 записей и 17 активных плагинов. Нагрузка `ab -n 500 -c 10`, замер с сервера.

| Параметр | Без кэша | WP Fastest Cache | WPFC + Varnish |
|---|---|---|---|
| Запросов/сек | 2,4 | 50,0 | 189,8 |
| TTFB главной, медиана | 3 025 мс | 48 мс | 20 мс |
| ab: p95 | 5 329 мс | 274 мс | 104 мс |
| Холодный запрос (сброс кэша) | — | 0,64 с | 0,67 с |

Для сравнения в тех же условиях: Breeze — 157 запросов/сек (TTFB 23 мс), связка Breeze + Varnish — 204 запроса/сек (21 мс).

## Плюсы

* Действительно простой: базовая настройка — одна галочка.
* Работает: 50 запросов/сек против 2,4 без кэша — это ~20-кратное ускорение.
* Самый быстрый «холодный» промах среди участников теста: при генерации кэша делает меньше обработки, чем Breeze (0,55–0,94 с против 0,69–0,89 с).
* Кэш чистится при публикации и обновлении записей, есть WP-CLI-команда очистки (`wp fastest-cache clear all`).

## Минусы

* **На nginx отдаёт кэш через PHP.** Фирменная быстрая раздача статики у WPFC работает через mod_rewrite в .htaccess, который nginx не читает. В итоге 50 запросов/сек против 157 у Breeze и 204 у связки с Varnish — втрое-вчетверо хуже.
* **Игнорирует `DONOTCACHEPAGE`.** На сайте с обязательным экраном согласия плагин закэшировал сам экран — вместе с вшитым CSRF-токеном — и раздавал его всем посетителям. Форма согласия с устаревшим токеном не работает ни у кого, кто получил закэшированную версию. Breeze и Varnish этот заголовок уважают.
* Браузерное кэширование и часть минификации — в расчете на .htaccess, на nginx не действуют.
* Значительная часть функций (CDN, оптимизация картинок, часть минификации) вынесена в платную версию.

## Вердикт

На Apache-шаред-хостинге WP Fastest Cache — разумный выбор: просто, популярно, работает. На связке nginx + Varnish теряет смысл: и медленнее, и опаснее за счёт игнорирования `DONOTCACHEPAGE`. Если Varnish уже стоит перед сайтом, он вытягивает WPFC с 50 до 190 запросов/сек — но до связки Breeze + Varnish (204) всё равно не дотягивает, а конфликт с экраном согласия остаётся.

Плагин оставлен установленным, но деактивированным — пригодится для повторных замеров.

Сравнение всех шести режимов (включая холодный старт и нагрузку на сервер) — в обзоре [Кеширование WordPress](./caching.md).
