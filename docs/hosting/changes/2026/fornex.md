# Fornex в 2026 году: сеть 300 Мбит/с, NVMe v5 и готовые AI-образы

- [Основной обзор Fornex](../../providers/fornex.md)

В 2026 году Fornex обновил сетевые условия европейских VPS, линейку дисков и готовые варианты развёртывания приложений.

## 300 Мбит/с в европейских локациях

27 февраля Fornex сообщил, что базовая скорость VPS в следующих локациях выросла до **300 Мбит/с**:

- Швеция;
- Нидерланды;
- Германия.

Для новых серверов скорость применяется сразу. Для уже работающего VPS провайдер рекомендовал выполнить перезагрузку через личный кабинет.

Также доступно увеличение канала до **1 Гбит/с**. Условия расширения и включённый объём трафика нужно проверять в панели перед оплатой.

Актуальная документация дополнительно указывает базовые 300 Мбит/с для России. В других локациях скорость может оставаться ограниченной 100 Мбит/с, поэтому значение нельзя автоматически переносить на все семь регионов Fornex.

### Что тестировать

```bash
iperf3 -c SERVER -P 5 -t 30
iperf3 -c SERVER -P 5 -t 30 -R
```

Нужно измерять:

- download и upload;
- один и несколько потоков;
- retransmits;
- пиковое и стабильное значение;
- задержку до РФ и целевой аудитории;
- поведение в разное время суток.

Скорость порта не гарантирует такую же скорость до любого внешнего оператора.

## Тарифы v5 и архитектура ARM

В актуальной документации действуют тарифы v5:

- Cloud NVMe для x86-64;
- Cloud ARM.

Для готовых тарифов заявлены:

- сеть 300 Мбит/с;
- разные лимиты чтения и записи;
- отдельные значения IOPS;
- минимальная частота CPU;
- автоматический переход со старой линейки v4.

Перед миграцией на ARM нужно проверить:

- наличие ARM64-образов;
- Docker images с платформой `linux/arm64`;
- бинарные расширения PHP/Node/Python;
- панели управления;
- backup agents;
- производительность конкретной базы данных;
- возможность быстрого возврата на x86-64.

## Классы NVMe

В конфигураторе доступны классы:

- NVMe Fast;
- NVMe Ultra;
- NVMe Max.

Название класса само по себе недостаточно. Для сравнения нужно сохранять:

- заявленные MB/s;
- read/write IOPS;
- latency `fio`;
- размер и тип тестового файла;
- direct I/O;
- результат повторного теста под нагрузкой.

Пример короткого теста:

```bash
fio --name=randrw \
  --filename=/root/fio-test.bin \
  --size=2G \
  --direct=1 \
  --rw=randrw \
  --rwmixread=70 \
  --bs=4k \
  --iodepth=32 \
  --runtime=60 \
  --time_based \
  --group_reporting
```

После теста файл нужно удалить.

## Готовые образы n8n и OpenClaw

13 февраля в новостной ленте Fornex появились готовые варианты для n8n и OpenClaw.

Такие образы ускоряют первый запуск, но перед production нужно проверить:

- кто собирает образ;
- версии Docker, приложения и базы;
- открытые порты;
- начальные credentials;
- автоматические обновления;
- расположение persistent data;
- резервное копирование;
- HTTPS и reverse proxy;
- возможность обычного обновления по официальной документации проекта.

Готовый образ не должен становиться «чёрным ящиком». После создания сервера полезно инвентаризировать containers, volumes, systemd units и firewall.

## Изменение оценки

Категорию **«Рекомендую»** менять не требуется. Увеличение скорости и более гибкие диски — положительные продуктовые изменения, но вывод по конкретному VPS должен опираться на фактические тесты.

Особенно важно не смешивать:

- скорость порта и реальную межоператорскую скорость;
- лимит диска и фактическую latency;
- удобный marketplace image и безопасно сопровождаемую production-установку.

## Checklist

- [ ] Проверена скорость именно в выбранной локации.
- [ ] Старый VPS перезагружен для применения нового сетевого профиля, если это требуется.
- [ ] Измерены оба направления `iperf3`.
- [ ] Проверены IOPS и latency выбранного класса NVMe.
- [ ] ARM протестирован со всеми бинарными зависимостями.
- [ ] Marketplace image проверен на версии, порты и credentials.
- [ ] Настроены внешний backup и restore-test.
