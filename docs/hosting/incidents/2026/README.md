# Инциденты хостингов в 2026 году

Последняя выборочная проверка свежих событий: **3 сентября 2026 года**. Последняя полная перепроверка всего watchlist: **31 августа 2026 года**.

Инциденты разделены по провайдерам. Массовые события, которые нельзя корректно отнести к одной компании, вынесены в отдельные разборы.

Отсутствие записи не означает отсутствие сбоев: у части провайдеров нет публичной status-панели или доступного архива. Время жизни status-записи также не всегда равно непрерывному простою каждого клиента.

## Проверка Selectel 3 сентября

Подтверждены три новых события разных уровней:

- **сетевые диски `universal.ru-7b`** — открытая с 31 августа деградация производительности; на 3 сентября нет финального update и root cause;
- **сеть `ru-3` и `ru-9`** — Major-инцидент 1–2 сентября длительностью 2 часа 25 минут;
- **KVM выделенных серверов** — открытая со 2 сентября проблема консолей для серверов с AMI BIOS.

Их нельзя объединять в «общее падение Selectel». Storage, сеть Cloud Platform и KVM относятся к разным слоям.

Сетевой Major-инцидент пересёкся по времени с заранее объявленными работами `ru-9`, но официальная status-запись не устанавливает причинную связь. Кроме того, проблема затронула и `ru-3`, поэтому писать «плановые работы вызвали аварию» без postmortem нельзя.

Категория Selectel остаётся **«Рекомендую»**, однако длительная деградация сетевых дисков стала отдельным флагом для наблюдения. Повторная оценка потребуется после закрытия записи и публикации деталей воздействия.

Подтверждены пять событий разных уровней:

- **27 августа, повторный S3-сбой Рег.облака** — 13:25–14:20 МСК; с кластера сняли нагрузку, после проверки работы и целостности данных вернули; данные не пострадали, причина ещё исследуется;

- **18 августа, внешний узел ММТС-9** — массовая инфраструктурная авария вне внутренней инфраструктуры REG.RU;
- **2 августа, один из ЦОД** — около 17:35 МСК инцидент затронул часть пользователей REG.RU и Рег.облака; сайты уже работали, но клиентские сервисы и серверы ещё восстанавливались;

Два S3-инцидента произошли с интервалом два дня. Сумма опубликованных окон — **3 часа 24 минуты**, но это не непрерывный простой. Второе событие сам провайдер назвал повторным. После него объединённая карточка REG.RU / Рег.облака перенесена из категории «Рекомендую» в **«Норм»**.

Для события 2 августа техническая причина и точное время полного восстановления не опубликованы. Для двух S3-сбоев также пока нет опубликованной root cause.

## Как читать журнал

Большое число записей не обязательно означает низкое качество провайдера. Крупная компания с открытой status-панелью может публиковать больше событий, чем небольшой провайдер без публичной истории.

Для практической оценки важны:

- продолжительность;
- повторяемость;
- data plane или control plane;
- число затронутых регионов;
- прозрачность;
- компенсация;
- внешние резервные копии;
- успешный restore-test.
