# Инциденты хостингов в 2026 году

Последняя проверка: **27 августа 2026 года**.

Инциденты разделены по провайдерам. Массовые события, которые нельзя корректно отнести к одной компании, вынесены в отдельные разборы.

Отсутствие записи не означает отсутствие сбоев: у части провайдеров нет публичной status-панели или доступного архива. Время жизни status-записи также не всегда равно непрерывному простою каждого клиента.

## Проверка REG.RU и Timeweb 27 августа

### REG.RU

После события ММТС-9 18 августа отдельного нового датированного инцидента REG.RU, который можно надёжно описать как самостоятельную аварию, не найдено.

Это не доказывает отсутствие локальных коротких сбоев. Журнал REG.RU обновлён датой проверки и разделением двух подтверждённых энергетических событий:

- собственный дата-центр 16 июля;
- внешний узел ММТС-9 18 августа.

### Timeweb

Обычный shared-хостинг и Timeweb Cloud проверяются отдельно.

В журнал Timeweb Cloud добавлен пропущенный Major-инцидент `de-1` 15 августа. Для обычного Timeweb-хостинга нового события с точной датой, затронутым сервером и финальным статусом в доступном архиве не найдено.

## Ближайшие плановые работы Selectel

### 28 августа — `ru-7`

С 09:00 до 15:00 МСК возможна краткая недоступность управления VM через API и панель. Работа сетей и уже запущенных VM не должна быть затронута.

### 1–2 сентября — `ru-9`

С 21:00 1 сентября до 01:00 2 сентября регион будет скрыт из панели, публичный API станет недоступен, а управление ресурсами может быть приостановлено до трёх часов. Запущенные ресурсы должны продолжить работу.

## Как читать журнал

Большое число записей не обязательно означает низкое качество провайдера. Крупная компания с открытой status-панелью может публиковать больше событий, чем небольшой провайдер без публичной истории.

Для практической оценки важны:

- продолжительность;
- повторяемость;
- data plane или control plane;
- число затронутых регионов;
- прозрачность;
- компенсация;
- внешние резервные копии;
- успешный restore-test.
