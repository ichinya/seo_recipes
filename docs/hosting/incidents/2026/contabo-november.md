## Дополнение 25 ноября — повторная деградация Auto Backup и перезагрузки VDS

Проверено 25 ноября по [официальной панели Contabo](https://contabo-status.com/).

- 24 ноября, 09:16 CET / 13:16 UTC+5: вновь отмечены задержки завершения Auto Backup EU из-за производительности хранилища. По заявлению поставщика, завершённые ранее копии не затронуты. Финал не опубликован.
- 24 ноября, 12:00 CET / 16:00 UTC+5: объявлена перезагрузка физических узлов VDS для активации исправления ядра хостов (идентификатор CVE-2026-99312 указан поставщиком, независимо не проверен). Ожидаемый простой 10–20 минут на VDS, индивидуальное окно не назначено. Завершение всех перезагрузок не подтверждено.

Проверить uptime, время загрузки, HTTP/HTTPS, фоновые службы и возраст последней завершённой копии; выполнить restore-test в отдельной среде. Плановый простой не равен измеренному. Object Storage EU остаётся отдельной записью. Категория «Рискованные / спорные» сохраняется.

Обновление Auto Backup от 23 ноября **не закрывает Object Storage EU**. Дата нового снимка не означает нового инцидента: хронология Auto Backup начинается с сообщения 2 ноября, Object Storage — 26 октября. Ни срок присутствия записи в панели, ни период наблюдения не являются доказательством непрерывного простоя всех клиентских ресурсов.

Для конкретного аккаунта проверить возраст последней завершённой копии, её доступность и восстановление в отдельную среду. Возможность читать копию и завершение нового задания зафиксировать раздельно. Заявление провайдера о восстановлении не заменяет такой тест; данные клиентов и restore здесь не проверялись. Категория **«Рискованные / спорные» сохраняется**.

На момент чтения уведомления присутствуют среди незавершённых, но это не измерение непрерывной недоступности каждого аккаунта. Точные начала воздействия и полный охват не опубликованы. Сентябрьскую паузу копирования нельзя автоматически считать той же причиной или непрерывным продолжением ноябрьского события.

Категория **«Рискованные / спорные» сохраняется**. Работающая VM не доказывает свежесть её копий. Практическая проверка — последняя завершённая копия, доступность содержимого, независимый экземпляр и тест восстановления в отдельную среду. Не перезаписывать единственную исправную копию и не запускать destructive restore на рабочем сервере ради проверки. Собственный restore-test здесь не выполнялся.
