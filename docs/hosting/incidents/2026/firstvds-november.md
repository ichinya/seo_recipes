## Практическая проверка после восстановления

Для своей VM сравнить HTTP-проверки приложения из независимых сетей с логами и часами панели. Не принимать доступность гипервизора за успешность запросов приложения.

Для S3 использовать только собственный тестовый бакет: небольшой уникальный объект, PUT → HEAD → GET, сравнение контрольной суммы, затем LIST с учётом модели согласованности выбранного сервиса. Ошибка LIST не доказывает потерю объекта, а доступная панель не доказывает работу API. Не удалять и не перезаписывать единственную резервную копию ради теста.

Проверку содержимого и метаданных при переносе проводить по [рецепту миграции S3](../../testing/s3-migration-verification.md). Зафиксировать время последнего пригодного backup и отдельно выполнить восстановление в изолированную среду. Эти клиентские тесты при подготовке статьи не выполнялись.
