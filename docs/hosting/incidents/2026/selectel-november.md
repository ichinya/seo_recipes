## Дополнение 24 ноября — API готового облака 1С в режиме чтения

**Проверено 24 ноября 2026 года (UTC+5).** [Карточка №413405](https://selectel.live/incidents/413405) опубликована **23 ноября, 18:32 МСК / 20:32 UTC+5**. При проверке она имеет классификацию `Minor incident` и обновление `Issue`; финальное сообщение о восстановлении не опубликовано.

Ограничение касается **API готового облака 1С в пуле `ru-3`**, с компонентами `ru-3a`, `ru-3b` и `ru-3c`. API переведён в режим чтения: возможны ошибки создания, управления и удаления ресурсов. Провайдер уточняет, что этот режим действует для функционала кластеров и информационных баз.

Это ограничение операций управления. Карточка **не подтверждает остановку работающих приложений 1С, перевод их пользовательских данных в режим чтения или потерю баз**. Время публикации не заменяет измеренное начало воздействия на конкретного клиента. Событие учитывается отдельно от backup `ru-3b` и S3 RU-1 ниже: общий регион не доказывает общую причину или одинаковый статус.

Владельцу ресурса следует сопоставить ошибки конкретной операции API с идентификатором кластера/ИБ и временем запроса, отдельно проверить доступность приложения и дождаться официального итога. Повторные создания и удаления ресурсов ради проверки не нужны. Клиентские проверки здесь не выполнялись; категория **«Рекомендую» для ранее оценённого VDS** сохраняется и не переносится автоматически на продукт готового облака 1С.

**Обновление 22 ноября — закрытие S3 RU-1.** [№413066](https://selectel.live/incidents/413066) содержит финальное сообщение о решении проблемы **21 ноября, 16:21 МСК**. Новая карточка №413079 — **не продолжение, автоматически объединяемое с прежним событием**. Общая первопричина, число затронутых клиентов и непрерывность ограничения не доказаны.

**Границы подтверждений:** проблемы создания новой копии не доказывают удаления уже созданных копий, отказа restore или остановки виртуальных машин. Проблема авторизации через указанный FTP-адрес не доказывает отказ всех операций S3 API либо потерю объектов.

**Практическая проверка backup:** прочитать состояние последнего задания, его время и возраст последней пригодной копии относительно RPO; настроить оповещение по пропущенным заданиям; проверить восстановление на изолированном тестовом ресурсе; убедиться, что независимая копия не зависит от той же точки отказа. Не считать успешный статус панели достаточным доказательством корректного restore.

**Практическая проверка хранилища:** разделить соединение с названным FTP-endpoint и прямые операции через документированный S3 API; безопасно проверить список и чтение маленького контрольного объекта только с разрешёнными ключами, собрать код ошибки и время, не публикуя секреты. Избегать удаления/перезаписи объектов на production.

**Категория:** существующее «Рекомендую» для протестированного VDS не меняется автоматически. Надёжность backup и S3 — отдельные продуктовые критерии. По повторяемости backup нужна дополнительная проверка RCA, длительности фактического воздействия и успешности восстановления.

**Открытый вопрос:** финал более ранней карточки №410193 и их техническая связь не подтверждены этой записью. Категория Selectel **«Рекомендую» для оценённого VDS** не переносится автоматически на качество backup-сервиса; категория пока не меняется.

## Оценка и проверка

Категория **«Рекомендую» для ранее протестированного VDS сохраняется**, но не является гарантией всех продуктов Cloud Platform. Повторяемость сетевых проблем и ограничения backup требуют отдельной оценки нужного продукта и сценария восстановления.

План диагностики: сравнить HTTP/TLS приложения из независимых сетей, состояние VM и управления; для backup проверить содержимое и результат восстановления. Передавать поддержке время с часовым поясом, регион и идентификатор ресурса, без секретов. Клиентские тесты, расчёт SLA и проверка целостности данных здесь не выполнялись.
