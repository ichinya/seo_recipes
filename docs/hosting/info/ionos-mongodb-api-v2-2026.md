## Отдельное security-окно 16 ноября: CVE-2026-118383

**Проверено 13 ноября 2026 года, Asia/Yekaterinburg (UTC+5).** [Объявление IONOS](https://status.ionos.cloud/incidents/xp1bvj2q2v5q) опубликовано **12 ноября, 12:57 UTC**, дополнено в **13:12 UTC**. Автоматическая установка патча для всех Managed MongoDB назначена на **16 ноября, 08:00–16:00 UTC / 13:00–21:00 UTC+5**. На дату проверки это план, не результат обновления.

IONOS выполняет патч самостоятельно. Для многорепличных кластеров заявлены последовательные перезапуски, возможны сбросы соединений и переключение primary; для одиночных — краткий перерыв. Строки подключения и DNS должны сохраниться. Клиенту нужно проверить обработку переподключений и допустимые повторы операций; критичные неповторяемые задания не назначать на это окно.

**Патч безопасности и переход management API — два разных изменения.** Обещание неизменности версий в объявлении API-миграции не отменяет отдельный security-патч. Завершение API-миграции также не доказывает установку исправления. Проверка версии, копии и приложения описана в [рецепте CVE-2026-118383](../testing/mongodb-cve-2026-118383.md). Результат на клиентских кластерах не проверялся.

## Объявленные изменения

Затронуты `us-mci` (Lenexa), `es-vit` (Logroño), `fr-par` (Париж), `gb-lhr` (Лондон). По заявлению IONOS, это смена инфраструктуры управления без переноса или пересоздания БД: строки подключения, DNS, версии MongoDB и текущие топологии сохраняются.

Многорепличные кластеры планируют переключать последовательно без остановки; у одиночных возможен короткий перерыв. Во время перехода региона v1 становится read-only, создание новых кластеров временно останавливается в обеих версиях API. После перехода запросы управления v1 перестают работать. Это план провайдера, не измеренный результат.

API v2 использует региональные адреса и Bearer/JWT вместо Basic Authentication:

| Регион | Endpoint из объявления |
| --- | --- |
| `us-mci` | `https://mongodb.us-mci.ionos.com/v2` |
| `es-vit` | `https://mongodb.es-vit.ionos.com/v2` |
| `fr-par` | `https://mongodb.fr-par.ionos.com/v2` |
| `gb-lhr` | `https://mongodb.gb-lhr.ionos.com/v2` |

Объявлены snapshots с retention 1–365 дней, неизменяемая после создания топология и прекращение Playground Edition. После начального пользователя дальнейшие пользователи и роли управляются непосредственно в MongoDB. Эти изменения не означают необходимости заменить пароль приложения облачным JWT.

## Предлагаемый план проверки клиента

1. Инвентаризировать API-скрипты, SDK, Terraform и аварийные процедуры. Сохранять имена файлов и выбранный регион, не значения токенов. Срок для своей операции уточнить до общего окна.
2. В отдельной ветке подготовить поддерживаемый SDK/API v2 и способ хранения токена. Не подставлять региональный адрес вслепую в старый запрос: проверить контракт нужной операции.
3. Выполнить согласованный read-only тест управления. Затем проверить Terraform plan без apply: миграция провайдера не должна случайно превратиться в удаление и пересоздание БД клиентским кодом. State и plan могут содержать секреты.
4. Отдельно проверить подключение приложения, восстановление независимой копии и повторяемость операций после переподключения. Доступный management API не доказывает сохранность данных; рабочий MongoDB-запрос не проверяет создание нового кластера.
5. Подготовить возврат к проверенной конфигурации v2 и альтернативный доступ поддержки. После отключения v1 возврат к нему нельзя считать рабочим откатом.

Создание платных тестовых кластеров, ротация токенов и применение Terraform требуют отдельного согласования. В этой работе такие действия не выполнялись. Полное окно не означает непрерывный простой всех баз; фактический результат и итоговый счёт не проверены. Категория провайдера не изменена.
