# Cloud.ru

[Cloud.ru](https://cloud.ru/partners/referral/form?referralCode=592010788096) - отдельный российский облачный провайдер. 

## Статус заметки

По текущему впечатлению Cloud.ru относится к более дорогим, но сильным по комплаенсу российским облакам. В заметках отдельно зафиксирован вариант с маркетинговыми условиями, где основная регулярная оплата может сводиться к публичному IP примерно за 150 рублей. Это нужно перепроверять перед использованием, потому что условия акций и тарификации меняются.

## Что известно

Cloud.ru развивает облачные и AI-сервисы для бизнеса. По официальной главной странице у провайдера больше 130 IaaS- и PaaS-сервисов, а в линейке есть виртуальные машины, хранилища, базы данных, Kubernetes, AI/ML и корпоративные инфраструктурные продукты.

Практический вывод:

- для простого дешевого VPS Cloud.ru может быть избыточным;
- для проектов с российской юрисдикцией, документами и требованиями ИБ это один из основных кандидатов;
- перед запуском нужно внимательно считать цену IP, дисков, снимков, трафика и managed-сервисов.

## Размещение и независимость зон: разъяснения 11 октября

**Выборочная проверка 12 октября 2026 года:** прочитаны два официальных материала, опубликованных **11 октября**. Это дата разъяснений, не дата открытия площадок. Старые цены и сертификаты ниже этой проверкой заново не подтверждались.

В [ответах о дата-центрах](https://cloud.ru/blog/data-tsentry-i-infrastruktura-cloud-ru) компания сообщает об аренде площадей в **девяти коммерческих ЦОД в России** с заявленным уровнем Tier III. Города, адреса и операторы этих площадок публично не раскрываются; сведения для аудита предлагается запрашивать через менеджера или поддержку. Это не девять новых или собственных дата-центров. Заявление об уровне Tier III не является проведённой редакцией проверкой сертификата каждой площадки или SLA каждого сервиса.

В [разъяснении Direct Connect](https://cloud.ru/blog/voprosy-i-otvety-o-direct-connect-na-platforme-advanced) перечислены зоны **Advanced**, регион `ru-moscow-1`: `ru-moscow-1a` (AZ1), `ru-moscow-1b` (AZ2), `ru-moscow-1c` (AZ3), `ru-moscow-1e` (AZ5). По сообщению компании, они размещены в разных ЦОД. Соответствие AZ конкретным площадкам не опубликовано. Этот перечень нельзя автоматически переносить на Evolution или VMware.

**Точка подключения Direct Connect — узел стыка сетей, а не указание места хранения данных.** Параметры подключения предоставляются при заказе услуги; для аудита нужно указать цель запроса и уточнить доступный состав документов. Адрес узла связи нельзя использовать для самостоятельного определения ЦОД нужной AZ.

### Что запросить и проверить до критичного размещения

Ниже — редакционные критерии проверки, а не сведения о найденных недостатках Cloud.ru.

| Вопрос | Что считать пригодным подтверждением |
| --- | --- |
| Разделение площадок | Документ по выбранным платформе, региону и AZ с датой и допустимым для аудита описанием размещения |
| Электропитание и охлаждение | Описание независимых контуров и общих зависимостей; один ярлык Tier III не описывает все коррелированные риски |
| Каналы и точки стыка | Схема резервирования, независимость трасс и операторов; два подключения к одному узлу не предполагаются независимыми |
| Общие сервисы | Зависимости IAM, DNS, API управления, KMS и мониторинга при отказе зоны |
| Данные и резервные копии | Фактическое размещение реплик и backup, доступ к ключам и восстановление вне отказавшего контура |
| Ёмкость и сроки восстановления | Квоты, наличие резервных ресурсов, согласованные RPO/RTO и результат учебного restore-test |

Запросите документы по своей архитектуре до оплаты критичного размещения, а не только общую презентацию. Проведите согласованный тест отказа в изолированном окружении: создание замены, доступ к данным, сети и внешнему мониторингу. Назначьте владельца проверки и сохраните результат в закрытом журнале; адреса, схемы и ограничения распространения полученных документов не публикуйте автоматически.

**Категория «Рекомендую» сохранена.** Раскрытие общей схемы полезно, но не доказывает независимость всех зависимостей, успешное переключение конкретного приложения или изменение SLA. Непубличность адресов сама по себе также не доказывает ненадёжность. Независимый аудит площадок и тест отказоустойчивости редакцией не выполнялись. Датированная запись — в [журнале изменений Cloud.ru](../changes/2026/cloudru.md).

## Сертификация и безопасность

По официальной документации Cloud.ru:

- все платформы Cloud.ru имеют уровень защиты 152-ФЗ УЗ-1;
- облачная платформа для ГИС аттестована для государственных информационных систем с первым классом защищенности К1;
- платформа "Облако VMware" аттестована по требованиям безопасности информации для третьей категории значимости объектов КИИ по 187-ФЗ;
- реализованы ISO/IEC 27001, ISO/IEC 27701, ISO/IEC 27017 и ISO/IEC 27018;
- есть документы по требованиям 719-П ЦБ РФ и ГОСТ Р 57580.1-2017;
- зоны доступности платформ VMware и Advanced соответствуют PCI DSS 3.2.1, а для Advanced также указан сертификат PCI DSS 4.0;
- указаны лицензии Роскомнадзора, ФСБ и ФСТЭК.

Важная оговорка из документации: Cloud.ru не становится оператором персональных данных вместо клиента. Ответственность за доступы, настройки и корректную обработку данных остается на клиенте.

## Быстрая проверка

Проверка 11 июня 2026 года из текущей сети:

- `https://cloud.ru/docs/overview/security-introduction/topics/compliance` открылся с HTTP 200 примерно за 1.3 секунды.

Это только проверка публичной страницы. Новый сервер не создавался.

## Плюсы

- Очень сильная публичная база по сертификатам, аттестатам и лицензиям;
- подходит для проектов, где важны российская инфраструктура и документы по ИБ;
- есть широкий набор IaaS/PaaS-сервисов;
- есть варианты для ГИС, КИИ, PCI DSS и ГОСТ Р 57580;
- можно проверять маркетинговые условия, если нужен недорогой старт в российском облаке.

## Минусы и риски

- Не бюджетный VPS-провайдер;
- для небольших проектов может быть сложнее и дороже простого VDS;
- комплаенс не снимает обязанности с клиента: нужны правильные настройки, документы и процессы.

## Что тестировать перед рекомендацией

- реальную стоимость минимальной VM с IP, диском, бэкапами и трафиком;
- доступность нужных сервисов для физлица, ИП или юрлица;
- скорость поддержки до оплаты и после создания ресурсов;
- правила по SMTP, PTR, антиабузу и DDoS;
- применимость сертификатов к конкретной услуге и архитектуре.

## Итог

Cloud.ru стоит держать как отдельный вариант для серьезных российских проектов, где важны документы, ИБ и регуляторные требования. Для простого дешевого VPS лучше сначала смотреть более легкие провайдеры.
