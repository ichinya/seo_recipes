# IONOS

IONOS — крупный немецкий хостинг и облачный провайдер. В заметку он попал по отзыву от 2 июня 2026 года: «говорят, что IONOS в РФ еще работает».

Этот отзыв не является рекомендацией. Текущая категория — **«Рискованные»**: главный вопрос для пользователя из России — не только характеристики VPS, но и возможность легально и стабильно завести аккаунт, оплатить услугу и не попасть под закрытие из-за резидентства.

Операционные статусы TXL, S3 и поддержки проверены **10 сентября 2026 года**, DBaaS-дедлайны — 7 сентября; старые примеры тарифов не являются новым ценовым замером.

## Что есть по тарифам

На немецкой странице VPS на момент проверки были указаны Linux VPS от 2 евро в месяц на первые 6 месяцев. В младшем тарифе `Linux S+` заявлялись:

- 2 vCPU;
- 2 ГБ RAM;
- 80 ГБ NVMe;
- установка 10 евро;
- неограниченный трафик до 1 Гбит/с;
- IPv6-сеть включена;
- 1 IPv4 включен, дополнительные IPv4 — 5 евро в месяц;
- Plesk Obsidian — 5 евро в месяц.

Также заявлены Windows Server, KVM-консоль, Cloud Panel, root-доступ и круглосуточная поддержка. Цены и промопериоды перед покупкой нужно перепроверять.

## Инциденты и операционные риски

В 2026 году официальная status-панель IONOS Cloud фиксировала:

- 8–9 сентября — сетевое событие DE/TXL с поэтапным восстановлением Compute, Storage и DBaaS; на 10 сентября `Monitoring`;
- 24 августа — 3 сентября, по опубликованному RCA: деградацию S3 `eu-central-1`; временная мера применена, постоянное исправление QoS ещё готовится;
- периодическую недоступность control plane Managed Kubernetes;
- ошибки provisioning, Cloud API и Data Center Designer;
- ограничения свободной емкости GPU;
- невозможность создать некоторые MongoDB-кластеры во Frankfurt East;
- временную остановку автоматического обслуживания Kubernetes из-за высокой нагрузки;
- 21–23 августа — невозможность резервировать и управлять IP blocks через DCD и API;
- два ограничения телефонной поддержки Cloud Support: 4–8 сентября и отдельно 8 сентября; оба закрыты.

- [Инциденты IONOS Cloud в 2026 году](../incidents/2026/ionos.md)
- [Официальная status-панель](https://status.ionos.cloud/)

Важно различать control plane и workloads: уже запущенные приложения могли работать, когда API управления кластером или создание новых ресурсов были недоступны. Ограничение Cloud Support также не означает остановку VPS или облачных баз.

## TXL: восстановление сервисов не равно закрытию записи

На 10 сентября [событие TXL](https://status.ionos.cloud/incidents/2b5lgdhvt047) остаётся в `Monitoring`. Провайдер связал сетевую проблему с недавней заменой маршрутизатора. Подробный таймлайн и проверка границ воздействия находятся в [журнале](../incidents/2026/ionos.md); итоговую длительность всего инцидента пока не фиксируем.

## S3 Object Storage: опубликован RCA

3 сентября в **13:39 UTC** IONOS отметил восстановление нормального времени ответа S3 в `eu-central-1`. Опубликованный **8 сентября** RCA уточнил более раннее начало воздействия и причину в QoS. Точный таймлайн, различие между периодом воздействия и окном сообщений, временное отключение rate limiting и незавершённое постоянное исправление разобраны в [журнале инцидентов](../incidents/2026/ionos.md).

Закрытие устраняет актуальное предупреждение о продолжающемся сбое, но не отменяет необходимость проверять S3 data plane отдельно от управления buckets и keys в DCD.

Для рабочей нагрузки полезны:

- synthetic `PUT` / `HEAD` / `GET` / `DELETE`;
- измерение p95/p99 latency;
- контроль timeout и HTTP 5xx;
- ограниченные retries с exponential backoff;
- checksum после чтения тестового объекта;
- мониторинг длительности backup и media jobs;
- независимая копия критичных данных у другого провайдера.

## DBaaS: миграции августа и дедлайн 28 сентября

Августовские миграции PostgreSQL/MariaDB и отключение In-Memory DB v1 отмечены завершёнными в status-панели. Это не подтверждает, что клиентские API, Terraform и SDK автоматически обновились.

Подробно:

- [IONOS DBaaS — миграции API v1 → v2 в августе–сентябре 2026](../info/ionos-dbaas-migrations-2026.md)

### PostgreSQL

Инфраструктурная миграция v1 → v2 завершена. **28 сентября, 14:00–16:00 UTC** запланировано окончательное отключение PostgreSQL API v1. Проверить management automation нужно до начала окна.

Актуальные условия:

- management API требует TOKEN authentication вместо BASIC;
- интеграции должны использовать региональный v2 endpoint;
- кластеры на HDD/SSD Standard переводились на SSD Premium с соответствующей тарификацией;
- optional Observability оплачивается отдельно;
- отключение старого management API, по уведомлению провайдера, не должно прерывать работу уже перенесённых баз.

TOKEN auth Cloud API не заменяет SQL-пользователя и пароль приложения. Отдельно проверяйте SQL-подключение и операции управления через Terraform/API/SDK.

### MariaDB

- с 17 августа нельзя создавать новые v1 clusters;
- окно автоматической миграции existing clusters 24–28 августа завершено;
- 31 августа завершено отключение MariaDB API v1;
- API scripts, Terraform и SDK должны использовать v2.

Сам database cluster может быть мигрирован автоматически, но это не обновляет клиентский IaC-код.

### In-Memory DB / Valkey

Августовский дедлайн уже прошёл:

- новые v1 instances запрещены с 4 августа;
- отключение v1 было назначено на 31 августа и отмечено завершённым;
- automatic migration не предусматривалась;
- клиент должен использовать v2 instance с перенесёнными необходимыми данными и новым endpoint;
- v2 использует Valkey;
- с 1 сентября действуют новые цены snapshot-возможностей.

Если In-Memory DB используется для sessions/queues/locks, это production-critical зависимость, а не обычный disposable cache. После EOL нельзя рассчитывать на rollback к работающему v1.

## Плюсы

- крупный европейский провайдер, не мелкий реселлер;
- есть VPS, облачные серверы и managed-сервисы;
- есть Linux и Windows;
- есть публичная информация по дата-центрам;
- инфраструктура IONOS Cloud размещается в США и Европе;
- есть открытая status-панель с техническими обновлениями;
- status page заранее публикует часть migration/deprecation deadlines.

## Минусы и риски

- в опубликованной политике IONOS указаны отказ от новых клиентских контрактов из России и прекращение существующих отношений с российскими клиентами;
- даже если сайт открывается и заказ технически проходит, аккаунт может попасть под проверку или закрытие позже;
- оплата российскими картами, адрес биллинга, телефон и документы могут стать проблемой;
- цены в евро, возможны НДС и комиссии;
- дополнительный IPv4 и панели управления могут быть платными;
- в облаке встречались сбои управляющего слоя и ограничения свободной емкости;
- в августе–сентябре зафиксированы как сбой Object Storage management, так и длительная деградация S3; опубликованный RCA не означает завершения постоянного QoS-исправления;
- сетевое событие TXL затронуло несколько инфраструктурных компонентов и на 10 сентября ещё находится в `Monitoring`;
- остановленный GPU-сервер при дефиците ресурсов может не запуститься повторно;
- managed products могут иметь обязательные API migrations с жестким deadline;
- автоматическая infrastructure migration не гарантирует, что Terraform/SDK/API automation обновится автоматически;
- PostgreSQL migration может изменить storage class и стоимость;
- In-Memory DB v1 требовал manual migration до отключения;
- недавние ограничения Cloud Support показывают риск получения помощи, хотя оба события уже закрыты.

## Что проверить

### Аккаунт и санкционные риски

- открывается ли сайт и личный кабинет напрямую из РФ;
- допускается ли новый договор с фактическим резидентством клиента;
- какие страны доступны в биллинге;
- проходит ли оплата разрешённым способом;
- какие KYC-документы потребуются;
- каковы условия прекращения договора и выгрузки данных.

### Инфраструктура

- какой дата-центр реально выдается;
- какой пинг и трассировка из РФ;
- можно ли быстро выгрузить бэкап или образ;
- достаточно ли свободной емкости в резервной локации;
- как приложение переживает недоступность Cloud API или Kubernetes control plane;
- как меняются S3 latency и error rate в рабочее время;
- есть ли независимый backup Object Storage и проверенный restore.

### DBaaS

- нет ли обращений к v1 API;
- нет ли hardcoded BASIC auth для management API;
- Terraform provider/modules актуальны;
- In-Memory DB переведен на v2;
- стоимость storage/snapshots после migration приемлема;
- restore процедуры проверены.

## Итог

Технически IONOS выглядит сильнее многих небольших VPS-провайдеров: это крупная компания, развитая инфраструктура и понятные дата-центры. Но для пользователя из РФ главный риск — аккаунт, оплата и санкционная политика.

Для IONOS Cloud дополнительно нужно учитывать:

- доступность и производительность data plane;
- доступность управляющего слоя;
- свободную емкость;
- migration/deprecation lifecycle managed services;
- возможность роста стоимости после infrastructure upgrade;
- доступность поддержки при восстановлении.

Категория остаётся **«Рискованные»**. Восстановление S3 и поддержки не отменяет оснований, связанных с аккаунтом, оплатой и санкционной политикой; технические события и выполнение корректирующих мер оцениваются отдельно.

Для важных проектов обязательны независимые бэкапы, IaC export и готовый план переезда.
