## Датированный повод

[Первое событие 14 ноября](https://www.cloudflarestatus.com/incidents/a643zcsfc71q) затронуло R2 и Tiered Cache; закрыто в 06:45 UTC. [Второе событие](https://www.cloudflarestatus.com/incidents/dpao7idy3zei) относится к WNAM-бакетам: ошибки заявлены за 19:41–20:03 UTC, последнее сообщение опубликовано в 20:20. Подробные времена и ограничения — в сетевом журнале. Два события не объединяются по одному совпадению продукта.

Диагностическая гипотеза: ошибка пути доставки не обязательно означает отказ origin или утрату объекта. Проверить это нужно наблюдениями; сама status-карточка не устанавливает причину ошибки конкретного проекта.

## Подготовить контрольный объект

Выбрать существующий небольшой несекретный объект в собственном тестовом наборе. До инцидента сохранить его эталонный SHA-256, размер и ожидаемый тип содержимого. Не делать приватный бакет публичным и не открывать обход WAF ради проверки.

Нужны два **уже разрешённых** пути к одному неизменяемому объекту: прямой и через CDN. Прямой путь пригоден только если он действительно исключает проверяемый слой; один CNAME не доказывает независимость маршрута. Для приватного объекта использовать согласованный read-only доступ, не помещать токены и подписанные URL в Git, shell history или публичный отчёт.

## Минимальная HTTP-проверка без записи в хранилище

Пример для двух публичных тестовых URL. Заменить `example.com` своими адресами; приватные ссылки сюда не вставлять. Объект должен быть небольшим. Нет PUT/DELETE, очистки кеша, автоматических повторов или перехода по redirect.

```bash
#!/usr/bin/env bash
set -euo pipefail
umask 077
out=$(mktemp -d)
printf 'Локальный отчёт: %s\n' "$out"

check_url() {
  local label="$1" url="$2"
  date -u '+%Y-%m-%dT%H:%M:%SZ' > "$out/$label.time"
  curl --silent --show-error --proto '=https' \
    --connect-timeout 5 --max-time 15 \
    -H 'Accept-Encoding: identity' \
    --dump-header "$out/$label.headers" \
    --output "$out/$label.body" \
    --write-out 'http=%{http_code} ttfb=%{time_starttransfer} total=%{time_total} bytes=%{size_download}\n' \
    "$url" > "$out/$label.metrics" || {
      printf 'Ошибка транспорта: %s\n' "$label" >&2
      return 1
    }
}

check_url direct 'https://storage.example.com/diagnostics/known-small-object.txt'
check_url cdn 'https://cdn.example.com/diagnostics/known-small-object.txt'
cat "$out/direct.metrics" "$out/cdn.metrics"
```

Сначала проверить HTTP-код, размер и тип содержимого. Сравнивать SHA-256 с эталоном только для успешного ответа с ожидаемым представлением: одинаковые страницы ошибок не подтверждают целостность объекта. Локальные `.headers` и `.body` могут содержать диагностические данные; перед публикацией отчёта их просмотреть и обезличить. Пример остановится при ошибке транспорта: для второго пути выполнить отдельный согласованный замер.

## Интерпретировать результаты

| Наблюдение | Следующая проверка, не готовый диагноз |
| --- | --- |
| Прямое чтение успешно, CDN возвращает ошибку | Правила кеширования, заголовки, идентификатор запроса и маршруты; одинаковый объект и момент времени |
| Оба пути ошибочны | Доступность хранилища, DNS, TLS, права, путь объекта и клиентская сеть |
| Работает из одного ASN, не работает из другого | Независимость сетей и прокси, IPv4/IPv6, маршрут и близкие временные окна |
| Ошибки исчезли до `Resolved` | Отдельно записать фактические наблюдения и время сообщения провайдера |

Для выводов о регионах нужны несколько независимых точек; два сервера одной сети не дают независимого подтверждения. Зафиксировать UTC, регион/ASN, URL без секретов, HTTP-код, TTFB и ожидаемое содержимое. Не повышать нагрузку серией запросов во время аварии.

## Проверить восстановимость отдельно

Чтение одного объекта не проверяет всю резервную копию. Для backup-сценария отдельно подтвердить дату, комплект файлов/дампа БД и восстановление в изолированной среде. Не удалять единственную копию и не запускать destructive sync. Успешный ответ панели, отсутствие 5xx или закрытая status-запись не заменяют этот тест.

Независимые сетевые ряды, клиентские пробы R2/CDN и восстановление данных при подготовке материала не выполнялись. Влияние на российскую аудиторию и индексирование конкретного сайта не установлено.
