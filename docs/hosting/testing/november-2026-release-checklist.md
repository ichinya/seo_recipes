# Ноябрь 2026 — проверка релизов для сайтов и CI

**Исходная проверка — 9 ноября 2026 года, UTC+5; дополнение ARM32 проверено 13 ноября.** Записи 3–6 ноября сохраняют прежнюю дату проверки; это не отчёт о выполненных тестах. Действующие настройки репозиториев, серверов и аккаунтов не менялись.

## WordPress 7.2 Beta 4 — 3 ноября

[Официальный релиз](https://wordpress.org/news/2026/11/wordpress-7-2-beta-4/) предназначен для тестовой среды, не для рабочих или критичных сайтов. В анонсе финал 7.2 запланирован на 8 декабря; это план из конкретной публикации, не подтверждённый выпуск. Календарь перед миграцией нужно проверить повторно.

Существующий [developer preview](../../cookbook/wordpress/wordpress-7-2-developer-preview.md) содержит более ранний контекст; эта запись не переаттестовывает его старые сроки. Для staging проверить тему и плагины, редактор блоков, REST API, Abilities API, ревизии и обновления переводов. Сохранить версии компонентов, результат каждого сценария и возможность возврата к исходной копии. Beta не заменяет установку стабильных security-обновлений production.

## Дополнение 22 ноября — PHP 8.6.0 GA и тесты совместимости WordPress

**PHP 8.6.0 выпущен 19 ноября 2026 года**: [официальный анонс](https://www.php.net/releases/8.6/en.php) и [архив релизов](https://www.php.net/archive/2026.php/). Предыдущий раздел RC5 ниже — историческая запись от 5 ноября, **не текущая рекомендация использовать RC**. GA означает стабильный статус PHP, но не поддержку каждой CMS, библиотеки или PHP-extension.

**20 ноября в 17:06 UTC** [команда WordPress опубликовала](https://make.wordpress.org/core/2026/11/20/php-wordpress-chat-nov-2026/) результаты обсуждения с PHP от 18 ноября: в тестах PHP 8.6 обнаружили (1) проблему отражения изображений GD через отрицательные размеры — ядро WordPress перешло на специализированную функцию, но плагины с копией старого подхода могут ломаться; (2) неверный MIME TrueType — исправлено в upstream PHP 8.6 RC7. WordPress оценил перспективу совместимости ядра **будущей версии 7.2** положительно, но совместимость плагинов прямо названа неопределённой. Это не результаты тестирования конкретного production-сайта.

### Минимальная матрица регрессии перед переходом на PHP 8.6

| Стек | Тестовый сценарий | Условие приёмки |
| --- | --- | --- |
| WordPress 7.1.x / 7.2 RC (только staging) | GD: отражение/поворот JPG и PNG, создание миниатюр, оптимизаторы изображений и EXIF orientation | Совпадает направление/размер результата; нет PHP warnings/errors; отдельный тест плагинов |
| WordPress и media | Определение TrueType MIME, загрузка шрифтов при разрешённой политике, WebP/AVIF | Ожидаемые MIME и файловый тип, правильная обработка и отсутствие регрессий |
| WordPress и PHP-FPM | Плагины, тема, WP-Cron, REST API, формы, загрузка медиа, кеш и email | Успешные интеграционные smoke-tests и чистые журналы ошибок |
| Laravel | `composer check-platform-reqs`, PHPUnit/Pest, очередь, schedule, image pipeline, cache, DB, CLI и FPM | Совместимость **реальных версий** Laravel, Symfony dependencies и расширений подтверждена тестами; наличие PHP GA не доказывает официальную поддержку фреймворком |
| MediaWiki | Composer/extensions, специальные страницы, изображения и thumbnail generation, задания и API | Тесты на поддерживаемой версии MediaWiki и расширений; статус поддержки PHP 8.6 отдельно сверить с официальной матрицей |

**Порядок:** сохранить версии PHP, расширений и приложения на исходном стенде; создать изолированную копию, восстановить данные и запустить контрольные тесты на текущем PHP и PHP 8.6 с одинаковым corpus. Проверить `php -v`, `php -m`, `composer check-platform-reqs`, `php -l` для значимых изменённых файлов и специализированные тесты приложения. Сохранить diff изображений и MIME, JSON-ответы API, HTTP-коды, логи FPM и длительности задач. Не смешивать потенциальную несовместимость пакета с новым дефектом PHP; при обнаружении регрессии зафиксировать минимальный воспроизводимый пример.

**Важная граница:** по доступной на момент проверки [матрице Laravel 13](https://laravel.com/docs/13.x/releases) официальная заявленная поддержка охватывает PHP 8.3–8.5; расширение до 8.6 не следует утверждать до обновления официальной документации. Для MediaWiki, PHP extensions и плагинов WordPress версии и матрицы также проверяются для конкретного проекта; здесь они не запускались.

**Внедрение:** сначала тестовая среда и rollback rehearsal, затем самостоятельное решение о production deploy. Не переключать PHP-FPM всех сайтов автоматически и не удалять старый runtime до подтверждения совместимости.

## PHP 8.6.0 RC5 — 5 ноября

[Архив PHP за 2026 год](https://www.php.net/archive/2026.php/) объявляет RC5 тестовым релизом; первый стабильный 8.6.0 запланирован на 19 ноября. Не переключать рабочий FPM на RC и не считать будущую дату гарантией выпуска.

В изолированной среде сравнить действующую версию PHP и RC: установку зависимостей, расширения, тесты приложения, deprecated-сообщения и HTTP-поведение через FPM. Проверка `composer check-platform-reqs` не заменяет интеграционные тесты и не подтверждает совместимость каждого плагина WordPress.

## Dependabot APM — 3 ноября

[GitHub объявил version updates для Agent Package Manager](https://github.blog/changelog/2026-11-03-dependabot-version-updates-support-agent-package-manager/): поддерживаемые Git-зависимости из `apm.yml`, обновление `apm.lock.yaml` при наличии. Это **не security updates** для APM. Внедрение относится только к проектам, действительно использующим такой манифест.

На отдельном тестовом репозитории проверить diff обновления, lockfile и совместимость инструкций агента. Изменённый skill или prompt — недоверенное содержимое до ревью, а не основание автоматически расширять доступы агента. Auto-merge не включать как побочный эффект знакомства с функцией.

## CodeQL 2.27.3 и 2.27.4 — 3–4 ноября

[2.27.3](https://github.blog/changelog/2026-11-03-codeql-2-27-3-adds-python-3-15-features-and-json-data-extensions/) добавляет JSON data extensions и опциональную модель угроз `ai` для LLM-generated data. Встроенных source-моделей у неё нет: требуется собственное описание источников. Изменения CFG GitHub Actions могут потребовать адаптации custom queries.

[2.27.4](https://github.blog/changelog/2026-11-04-codeql-2-27-4-improves-accuracy-and-query-metadata/) улучшает точность ряда запросов и проверку symlink при упаковке/публикации CodeQL packs. Для сравнения использовать один commit и query suite, сохранить версии, SARIF и разницу находок. Меньше alerts не означает отсутствие уязвимостей. Пример для поддерживаемой части приложения, например JavaScript/TypeScript, не выдавать за анализ всего PHP-бэкенда.

## Copilot Code Review API — 6 ноября

[Анонс GitHub](https://github.blog/changelog/2026-11-06-copilot-code-review-api-management-and-review-overview-updates/) добавляет управление настройками через REST/GraphQL и атрибуцию AI-ревью: уровень проверки и заявленные источники комментария — skills, MCP, instructions.

Первый этап — read-only inventory доступных настроек и разрешений на уровне repository/organization/enterprise. Не обещать одинаковую поддержку токенов на всех уровнях. Автоматическое ревью, изменение политики, подключение MCP и расходы требуют отдельного решения. Заявленный источник комментария не доказывает истинность самого замечания.

## ARM32 в GitHub-hosted runners — анонс 12 ноября

**Проверено 13 ноября 2026 года, UTC+5.** [GitHub объявил](https://github.blog/changelog/2026-11-12-actions-for-arm32-linux-windows-retirement/) прекращение поддержки ARM32-заданий Windows/Linux на hosted runners **к 8 декабря 2026 года**, включая нативное выполнение AArch32 user-space. В анонсе это связано с завершением поддержки Node 20 и отсутствием ARM32 в Node 24. Точный час перехода не указан.

Это не прекращение поддержки всей ARM64-архитектуры и не автоматический запрет выпуска ARM32-артефактов посредством кросс-компиляции. Последнее требует отдельной проверки toolchain; работоспособность произвольного self-hosted runner тоже не гарантируется данным анонсом.

Предлагаемый read-only аудит: найти ARM32/AArch32-зависимости в workflow, контейнерах, actions и загружаемых бинарниках; разделить архитектуру runner, среду исполнения action и целевой артефакт. В копии CI проверить поддерживаемый runtime и тесты итогового артефакта. Смена одного `runs-on` не заменяет эту проверку. Не обходить ограничения закреплением устаревшего небезопасного runtime. Рабочие workflow и платные runner-ресурсы здесь не изменялись.

## Результат проверки

Заполнить для каждого теста: версия, среда, источник и дата, ожидаемый результат, фактический результат, ограничения и решение внедрить/отложить. Сейчас фактические результаты не получены. [Памятка о cloud secrets](./github-secret-scanning-cloud-credentials-2026.md) дополняет этот список, но не гарантирует обнаружение секретов во всех источниках.
