# Cloudflare Search for Agents

**Проверено по документации 26 ноября 2026 года.** [Анонс 25 ноября](https://developers.cloudflare.com/changelog/post/2026-11-25-search-for-agents/) описывает beta-функцию поиска по содержимому сайта. Она возвращает найденные фрагменты Markdown с источниками, а не сгенерированный ответ. Это отдельный индекс AI Search, не индекс Google, не гарантия цитирования в AI-ответах и не замена sitemap, robots.txt или обычного поиска.

## Пилот

1. Используйте отдельную тестовую зону Cloudflare с небольшим набором заведомо публичных страниц. Не подключайте закрытую документацию, персональные данные или источник с привилегированными заголовками авторизации. До включения проверьте состав публичного корпуса, отсутствие конфликтующего маршрута /.well-known/search и бюджет аккаунта.
2. В Overview зоны, Quick Actions, включите Search for Agents, изучите настройки и условия тарификации, подтвердите. Будет создан instance в namespace default.
3. В AI Search проверьте источник, path filtering, статусы обработки, ошибки и число проиндексированных элементов. По умолчанию Discover обходит ссылки и sitemap, глубина 5 переходов, поддомены выключены, синхронизация каждые 24 часа. Используется гибридное извлечение, максимум 10 фрагментов, similarity cache включён на 48 часов. Это настройки по умолчанию, не SLA свежести; проверьте актуальные значения экземпляра.
4. До подключения основного сайта убедитесь, что результаты не раскрывают исключённые страницы. WAF и AI Crawl Control применяются к запросам endpoint; не отменяйте защиту целиком ради теста.

См. [инструкцию Cloudflare](https://developers.cloudflare.com/ai-search/how-to/search-for-agents/), [фильтрацию путей](https://developers.cloudflare.com/ai-search/configuration/indexing/path-filtering/) и [политику AI-краулеров](./cloudflare-ai-crawlers.md).

## Проверка discovery и HTTP

Нужны Bash, curl и Python 3. Подставьте собственный HTTPS-домен и запрос к существующей тестовой статье. Сохраняйте артефакты локально, не отправляйте секреты в поисковых запросах. Команды не меняют конфигурацию.

```bash
set -eu
BASE='https://example.com'
OUT=$(mktemp -d)
Q='Как проверить доступность сайта?'
curl -sS --max-time 30 -D "$OUT/html.headers" \
  -H 'Accept: text/html' -o "$OUT/page.html" "$BASE/"
python3 - "$OUT/page.html" "$BASE" <<'PY'
from html.parser import HTMLParser
from pathlib import Path
import sys
class Meta(HTMLParser):
    def __init__(self):
        super().__init__()
        self.values = {}
    def handle_starttag(self, tag, attrs):
        a = dict(attrs)
        if tag == "meta" and a.get("name", "").startswith("agent:"):
            self.values[a["name"]] = a.get("content", "")
p = Meta()
p.feed(Path(sys.argv[1]).read_text(encoding="utf-8"))
for key, value in p.values.items():
    print(key, value)
assert p.values.get("agent:endpoint") == sys.argv[2] + "/.well-known/search?q={query}"
assert p.values.get("agent:method") == "GET"
assert p.values.get("agent:instructions")
assert p.values.get("agent:documentation")
PY
curl -sS --max-time 30 -D "$OUT/markdown.headers" \
  -H 'Accept: text/markdown' -o "$OUT/page.md" "$BASE/"
curl -sS --max-time 30 --get "$BASE/.well-known/search" \
  --data-urlencode "q=$Q" -D "$OUT/get.headers" -o "$OUT/get.md" \
  -w 'GET %{http_code} %{content_type} %{time_total}\n'
curl -sS --max-time 30 -X QUERY "$BASE/.well-known/search" \
  -H 'Content-Type: text/plain' --data-binary "$Q" \
  -D "$OUT/query.headers" -o "$OUT/query.md" \
  -w 'QUERY %{http_code} %{content_type} %{time_total}\n'
printf 'Artifacts: %s\n' "$OUT"
```

HTML должен содержать четыре discovery meta-поля: instructions, endpoint, method, documentation. При отдельно включённом Markdown for Agents проверьте YAML front matter с полем agent; если функция выключена, отсутствие этой разметки не ошибка Search for Agents. Для QUERY также поддерживается JSON с полем q. Проверяйте HTTP 200, фактический Markdown, ссылки на разрешённые источники и релевантность; HTML challenge, redirect, 403, 429 или 5xx не являются успешной выдачей. GET и QUERY могут иметь разные задержки; идентичность текста не обязательна. При 429 остановитесь и проверьте лимиты, не запускайте бесконечные повторы.

## Проверка качества и свежести

Составьте до теста эталонный набор запросов и допустимых URL. Для SEO Recipes можно начать с такого набора (конкретные опубликованные URL взять из sitemap тестового домена):

| Запрос | Ожидаемый материал |
| --- | --- |
| Как проверить доступность VPS по IPv6? | Тестирование VPS |
| Как проверить очистку CDN-кеша? | Cloudflare purge-by-URL |
| Как проверить подлинность Googlebot? | Документация о Google и проверке роботов |
| Как восстановить резервную копию? | Материал о backup/restore |
| Как приготовить вымышленное блюдо ZX-TEST-987? | Нет релевантного результата |

Расширьте набор до 20 вопросов, включив русский и английский, точные термины и перефразировки. Для каждого сохраните UTC, метод, HTTP-код, время ответа, первые пять уникальных URL, оценки релевантности и решение проверяющего. Считайте Hit@5 (доля запросов с ожидаемым URL среди первых пяти), MRR (среднее обратное место первого подходящего URL, ноль если отсутствует), p50/p95 задержки и долю ошибок. Оценки Cloudflare сами по себе не доказывают правильность результата.

Для проверки свежести разместите уникальный безвредный маркер на публичной тестовой странице, запишите время публикации, дождитесь следующей синхронизации и проверяйте его небольшим числом запросов. Затем замените маркер, проверьте новую версию и отсутствие старой после переиндексации и обновления кеша. Различайте дату обхода, завершение индексирования и выдачу из similarity cache. Для исключённого пути используйте только синтетический несекретный маркер; его появление в выдаче — основание остановить пилот. Не считайте robots.txt механизмом авторизации.

Предлагаемые критерии пилота: Hit@5 не ниже 80% на заранее размеченных 20 запросах, отсутствие непубличных результатов, отсутствие неожиданных HTTP-ошибок, свежесть и задержки в согласованных пределах. Это локальные критерии, не гарантии поставщика.

## Стоимость

По [тарифам AI Search](https://developers.cloudflare.com/ai-search/platform/limits-pricing/), проверенным 26 ноября, биллинг начинается 1 декабря 2026 года. Включённый месячный объём на аккаунт: 5 млн ingestion tokens, 10 GB-month хранения, 1000 semantic и 1000 full-text запросов. Workers Free ограничивает обход 500 страницами в день. Учитывайте потребление других instances того же аккаунта.

| Сверх включённого | Цена USD |
| --- | --- |
| Ingestion | 0,75 за 1 млн токенов |
| Обработка изображений | дополнительно 0,50 за 1 млн токенов |
| Хранение | 2 за GB-month |
| Semantic/vector/hybrid | 0,75 за 1000 запросов |
| Full-text | 0,10 за 1000 запросов |

Пример: 10 000 гибридных запросов за месяц при полностью свободной квоте дают 9000 сверх лимита, то есть $6,75 за запросы по опубликованной ставке, без хранения, ingestion, налогов и иных услуг. Это модель, не гарантия доступности превышения лимитов на Free. Проверяйте план, фактическую тарификацию и счётчик в аккаунте. Повторная индексация и overlap фрагментов могут увеличивать ingestion. Генерация и внешние модели тарифицируются отдельно при использовании соответствующих функций; сам endpoint не генерирует ответы.

Перед расширением пилота задайте допустимый расход, снимите usage до/после ограниченной серии запросов и проверьте доступные ограничения и уведомления. Не предполагайте, что уведомление автоматически прекращает расходы.

Для агентов с возможностью изменения подписок используйте [отдельный рецепт контроля финансовых действий CLI/MCP](../../hosting/testing/cloudflare-agent-billing-controls.md). Согласие на пилот поиска не означает согласие на активацию платного продукта.

## Откат

Отключите Search for Agents в тестовой зоне и проверьте отсутствие discovery и доступной выдачи. Проверьте отдельно оставшийся AI Search instance, его индекс и другие публичные endpoints; не предполагайте автоматического удаления данных или прекращения расходов. Удаление instance выполняйте только после проверки зависимостей и явного согласования. Сравните обычный HTML и доступность сайта до и после.
