# 404, 410 и soft 404

27 ноября 2026 Google перенёс актуальные рекомендации в [документацию об ошибках сканирования](https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors). Это уточнение документации, а не новый алгоритм. Проверка источника: 28 ноября.

| Сценарий | Ответ |
| --- | --- |
| URL отсутствует или удалён без замены | 404 или 410 |
| Есть равноценная постоянная замена | 301 или 308 на неё |
| Страница существует | 200 с полноценным содержимым |
| Временная перегрузка | 429 или 503 по ситуации, устранить причину |

Soft 404 — классификация поисковой системы, например когда страница с кодом 200 фактически сообщает об отсутствии материала или редирект ведёт на нерелевантную главную. Это не отдельный HTTP-код. Google не снижает crawl capacity из-за известных 404/410 так, как при перегрузке и 5xx; обход бесполезных URL всё равно может расходовать ресурсы. Не блокируйте удалённый публичный URL в robots.txt только ради сокрытия 404: робот должен увидеть статус. Уберите URL из sitemap и внутренних ссылок. Для конфиденциальных данных используйте авторизацию, а не robots.txt.

## Воспроизводимая проверка

Подставьте свой тестовый домен и маршруты, сохраните GET без автоматического перехода по редиректу:

```bash
BASE=https://example.com
OUT=$(mktemp -d)
for path in /existing /missing-fixture /removed-fixture /moved-fixture; do
  name=${path#/}
  curl -sS --max-time 20 -D "$OUT/$name.headers" -o "$OUT/$name.html" \
    -w '%{http_code} %{content_type}\n' "$BASE$path" || exit 1
done
grep -Ei '^(HTTP/|location:|content-type:)' "$OUT"/*.headers
```

Ожидаемые коды: 200, 404, 410 (или 404 по выбранной политике), 301/308. Проверьте тело и конечный URL редиректа отдельно. В браузере проверьте отрисованный DOM и запросы API: пустая SPA с 200 может стать soft 404. Search Console URL Inspection и Page indexing помогают подтвердить классификацию Google; локальная эвристика не является диагнозом.

## Реализация

- WordPress: штатный 404 шаблон должен сохранять статус; проверьте плагины перенаправлений и кеш.
- Laravel: отсутствующая модель через route model binding или abort(404), намеренно удалённый ресурс через abort(410); редирект только на релевантную замену.
- Nuxt: серверный createError с statusCode 404 для отсутствующего ресурса; проверьте SSR и прямой запрос, не только клиентскую навигацию.
- Статический сайт: настройте 404 документ на хостинге с настоящим статусом; не переписывайте все отсутствующие маршруты на index.html с 200.

Существующий browser-run-seo-audit можно расширить эвристикой статуса, маркеров отсутствия и пустого DOM в audit.mjs; index.mjs является точкой запуска, не анализатором. В этой задаче инструмент не изменён. Не маркируйте эвристику как подтверждённый Google soft 404.
