# Review и AggregateRating в Google

24 июля 2026 года Google обновил правила **review snippets** и отдельно запретил добавлять на страницу и в структурированные данные поддельные отзывы и **нераскрытые стимулированные отзывы**.

Это важно не только для сайтов-отзовиков. `Review` и `AggregateRating` используют интернет-магазины, каталоги, рецепты, приложения, фильмы, мероприятия и другие проекты, которые рассчитывают на расширенный сниппет со звездами.

## Главное изменение 2026 года

Google прямо приводит два проблемных сценария:

- отзыв не основан на реальном опыте использования товара или услуги;
- автор получил деньги, скидку, купон, бесплатный товар или другое вознаграждение, но это не раскрыто пользователю ясно и заметно.

Сам факт вознаграждения не описан как абсолютный запрет. Проблема — скрытая мотивация. Если отзыв стимулирован, это должно быть понятно читателю на самой странице, а не только из JSON-LD или условий акции.

## Review и AggregateRating: в чем разница

`Review` описывает конкретный отзыв отдельного автора.

`AggregateRating` описывает сводную оценку на основе нескольких оценок или отзывов.

Типичная схема:

```json
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Пример товара",
  "aggregateRating": {
    "@type": "AggregateRating",
    "ratingValue": "4.7",
    "reviewCount": "128"
  }
}
```

Разметка не создает право на rich result сама по себе. Google может не показывать звезды даже при технически корректном JSON-LD.

## Что должно быть видно пользователю

Google требует, чтобы размеченная информация реально присутствовала на странице.

Если в JSON-LD указано:

```json
"ratingValue": "4.8",
"reviewCount": "250"
```

пользователь должен видеть соответствующую оценку и понимать, откуда она взялась.

Плохая практика:

- рейтинг существует только внутри JSON-LD;
- число отзывов отличается от видимого счетчика;
- размечаются отзывы, которых нет на странице;
- рейтинг собирается из другой категории или другого товара.

## Нельзя агрегировать отзывы с чужих сайтов

Google отдельно указывает: не нужно собирать в `AggregateRating` отзывы и оценки с других сайтов.

Например, не стоит делать так:

```text
Google Maps: 4.8
Яндекс Карты: 4.7
Другой каталог: 4.9
Итого на нашем сайте: 4.8
```

и затем размечать `4.8` как собственный `AggregateRating`, если это просто математическое объединение сторонних оценок.

## Self-serving reviews для LocalBusiness и Organization

Для локальных компаний и организаций действует дополнительное ограничение.

Если организация контролирует размещение отзывов **о самой себе**, её страницы с `LocalBusiness` или `Organization` не подходят для звездного review feature. Это относится и к ситуации, когда на собственном сайте встроен сторонний виджет отзывов о той же компании.

То есть наличие реальных отзывов в Google Business Profile или другом сервисе не означает, что можно вывести их на своем сайте и получить собственные звезды в органической выдаче через `AggregateRating`.

## Стимулированные отзывы

### Допустимый сценарий

Покупателю отправили письмо:

> Оставьте честный отзыв о покупке. После публикации вы получите купон на 300 ₽. Вознаграждение не зависит от оценки.

На странице рядом с таким отзывом явно указано:

```text
Автор получил купон за публикацию отзыва.
```

Так пользователь понимает контекст.

### Рискованный сценарий

```text
Поставьте 5 звезд и получите скидку 10%.
```

Здесь есть сразу несколько проблем:

- вознаграждение зависит от положительной оценки;
- итоговый рейтинг системно искажается;
- если мотивация скрыта, отзыв дополнительно нарушает новое правило Google.

Для SEO и доверия лучше вознаграждать сам факт честной обратной связи, а не нужную оценку.

## Практическая таблица

| Сценарий | Размечать | Комментарий |
| --- | --- | --- |
| Реальный отзыв клиента на странице товара | Да | Если отзыв виден пользователю и относится к конкретному товару |
| Средняя оценка собственных отзывов товара | Да | `AggregateRating` должен соответствовать данным на странице |
| Отзыв за бесплатный товар с явным disclosure | Осторожно | Стимулирование должно быть ясно раскрыто |
| Отзыв за скидку без disclosure | Нет | Google прямо запрещает undisclosed incentivized reviews |
| Придуманный отзыв | Нет | Поддельные отзывы запрещены |
| Средний рейтинг из нескольких сторонних площадок | Нет | Google не рекомендует агрегировать отзывы с других сайтов |
| Компания размечает собственный рейтинг как `LocalBusiness` | Нет для звездного feature | Self-serving review restriction |
| Каталог собирает отзывы пользователей о сторонних компаниях | Да, при соблюдении правил | Оценки должны исходить непосредственно от пользователей |

## Проверка JSON-LD

После изменения шаблона:

1. открыть [Rich Results Test](https://search.google.com/test/rich-results);
2. проверить обязательные свойства;
3. убедиться, что данные совпадают с HTML страницы;
4. проверить несколько реальных URL, а не только тестовый пример;
5. после выкладки смотреть отчеты Search Console по structured data;
6. отслеживать резкое падение числа valid items после релиза темы или плагина.

## Что проверить в CMS

### WordPress

Проверить, кто генерирует разметку:

- SEO-плагин;
- WooCommerce;
- плагин отзывов;
- тема;
- кастомный код.

На реальном сайте нередко одновременно выводятся два или три независимых JSON-LD-блока с разными значениями рейтинга.

Быстрый поиск:

```bash
curl -fsSL https://example.com/product/ | grep -o 'AggregateRating\|Review' | sort | uniq -c
```

Для полноценной проверки лучше смотреть исходный JSON-LD, а не только наличие строк.

## Чек-лист перед публикацией

- [ ] Каждый размеченный отзыв относится к конкретному объекту.
- [ ] Текст и рейтинг видны на странице.
- [ ] `ratingValue`, `ratingCount` и `reviewCount` соответствуют фактическим данным.
- [ ] Нет импортированного общего рейтинга с чужих сайтов.
- [ ] Нет выдуманных отзывов.
- [ ] Вознаграждение за отзыв явно раскрывается.
- [ ] Вознаграждение не используется для покупки только положительных оценок.
- [ ] Для `LocalBusiness` и `Organization` учтено ограничение self-serving reviews.
- [ ] JSON-LD проходит Rich Results Test.
- [ ] После релиза проверяется Search Console.

## Если звезды исчезли

Проверять стоит не только синтаксис Schema.org.

Порядок диагностики:

1. убедиться, что тип объекта вообще поддерживается Google для review snippet;
2. проверить соответствие видимого контента JSON-LD;
3. исключить self-serving scenario;
4. проверить источник рейтинга;
5. проверить, не изменился ли шаблон после обновления CMS;
6. убедиться, что отзывы не скрыты от пользователя;
7. проверить Search Console и Rich Results Test;
8. учитывать, что Google не гарантирует показ rich result даже при корректной разметке.
